# GameVault · 我的游戏生涯

记录玩过的游戏、当前进度、以及接下来想玩的计划。
Steam 库自动同步，进度和感想自己写。

> **数据是你自己的。** 这个工具不自带任何人的游戏数据 —— 你克隆下来第一次打开是
> **空库**，跑一次同步脚本导入你自己的 Steam 库。所有记录都存在你自己的浏览器里。
>
> 仓库里**有意不包含**：任何人的游戏库、Steam API Key、SteamID。
> 上传前请跑一次 `python scripts/check_repo_leak.py`（见「开发与安全」）。

## 快速开始

### 1. 拿到代码

```bash
git clone <仓库地址>
cd gamevault
```

### 2. 打开应用

直接双击 `index.html` 就能用（不需要服务器、不需要构建）。

> 如果浏览器提示跨域问题，用本地服务器打开：
> ```bash
> python -m http.server 8777
> ```
> 然后访问 http://127.0.0.1:8777

⚠️ **第一次打开是空库，这是正常的** —— 仓库里不含任何游戏数据。下一步把你自己导进去。

### 3. 导入你自己的 Steam 数据

```bash
cp .env.example .env      # 填入自己的 STEAM_API_KEY 与 STEAM_ID
python scripts/sync.py    # 生成 data/steam_sync.json
```

然后回到应用，点**「同步」**按钮，选那个文件即可。

> 🖥️ **桌面版（`.exe` / `python desktop/main.py`）不用做这一步** ——
> 它自己就能读本机 Steam 文件，点「同步」当场读完。见
> [桌面版：同步按钮点一下就同步](#桌面版同步按钮点一下就同步)。
> 上面这套「跑脚本 + 选文件」是给**浏览器版**（读不到你的硬盘）用的，
> 也可以当**数据备份**的导入端（导出入口在「设置 → 数据备份」里）。

> 没有 Key 也能先跑起来：本机装了 Steam 客户端的话，脚本会自动读本地文件，
> 拿到**库里已安装/玩过的那部分**（含全部游玩时长）与本地封面，
> 这一步**不联网、不需要 Key**。Key 是用来补「完整库 + 成就 + 愿望单」的。

想顺便刷新发售年份和分类：

```bash
python scripts/sync.py --refresh-store
```

常用参数：

| 参数 | 作用 |
|---|---|
| `--key <KEY>` | Steam Web API Key（不给则读环境变量 / `.env`） |
| `--sid <SteamID64>` | 查谁的库（不给则读环境变量 / `.env`，或从本机 Steam 自动识别） |
| `--refresh-store` | 联网补查商店信息（发售年份 / 类型） |
| `--refresh-ach` | 联网重查成就（慢） |
| `--steam-root <路径>` | 手动指定 Steam 安装目录（默认自动探测） |
| `--no-collections` | 跳过本地收藏夹读取 |
| `--out <路径>` | 输出位置（默认 `data/steam_sync.json`） |

> 不联网也能跑 —— 默认纯用 `data/.cache/` 里的缓存，秒出结果。
> **本地收藏夹读取永远不影响联网与否。**

拿到 Key：<https://steamcommunity.com/dev/apikey>
（前提：账号**非受限** —— 累计消费 $5 以上，且绑了手机令牌。）

### 4. （可选）让它成为「打开就有」的初始数据

```bash
python scripts/build-embed.py     # 由 data/steam_sync.json 生成 js/seed-data.js
```

生成后双击 `index.html` 就直接有数据了（`file://` 下读不了 json，所以要内联一份）。

⚠️ `js/seed-data.js` 是**你的个人数据**，已被 `.gitignore` 挡住，**不要提交**。

## 六个区块

| 区块 | 含义 | 谁会进来 |
|---|---|---|
| **我的游戏单** | 我有的 + 打算买的 + 玩过的总览 | 自动（同步时全进） |
| **待游玩** | 想玩但没开始 | 手动添加；愿望单导入的也落这里 |
| **正在游玩** | **90 天内启动过** | 自动；也可手动 |
| **暂停区** | **超过 90 天没启动** | 自动；也可手动 |
| **已通关** | 打完了，已归档 | Steam 收藏夹「已完结」→ 自动；全成就 → 自动；也可手动 |
| **放弃区** | 不打算再玩了，已出局 | 只能手动（暂停区可批量） |

> 上表里的收藏夹名是**默认值**。收藏夹是你自己在 Steam 里建的、名字随心，
> 所以应用不写死它 —— 在顶栏 **「设置」** 里告诉它哪个名字代表什么即可，
> 见 [收藏夹名字不一样怎么办](#收藏夹名字不一样怎么办)。

**「我的游戏单」是全集，其余五个是状态视图。** 同一款游戏只会在一个状态区里，
但它始终属于「我的游戏单」—— 所以总览永远能看到全部游戏（含愿望单里还没买的）。

> 状态区是**同一批游戏的筛选视角**，不是把游戏从总览搬走。
> 你在「暂停区」看到的游戏，在「我的游戏单」里照样能找到。

### 「我的游戏单」里的两段

总览不把工具和游戏混在一起排 —— 打开「我的游戏单」你会看到：

```
🎮 游戏
  [卡片...]

- - - - - - - - - - - - - - - - - -   ← 虚线分隔

🛠️ 工具 / 软件
  [卡片...]                          ← 整体压暗，悬停才亮
```

游戏段在上，工具段在下方单独隔开（虚线 + 加大间距），
工具卡片平时半透明，鼠标移上去才恢复正常 —— 不抢游戏区的视线。

判定标准是**它是不是游戏**（看商店分类和名称特征），
而不是「你有没有把它藏起来」。所以被收藏夹藏起来的真游戏
不会跑到工具段里去，它们只是默认不显示。

### 来源角标：它到底是买的还是想买的

「我的游戏单」与「待游玩」里，卡片封面**右下角**会挂一个来源角标：

| 角标 | 含义 |
|---|---|
| **已拥有** | 它在你的 Steam 库里 |
| **未入库** | 它只在愿望单里，你还没买 |
| （不挂） | 手动添加的 —— 判断不了，就不标 |

买了之后角标会**自动翻成「已拥有」**（下次同步时）。
但**位置不动** —— 没启动过的仍留在「待游玩」，等你真的开始玩，
启动日期才会把它带进「正在游玩」。

### 愿望单

云端版同步时会自动拉愿望单，把还没买的加进「待游玩」，并挂「未入库」角标。

- 愿望单接口**只给 appid 不给名字**，所以刚导入的款标题是空的，
  卡面/详情页先显示 `App <appid>` 占位（压暗）——
  **这是纯显示，不会往库里写假名字**。名字会分几轮同步陆续补齐。
- 「既在库又在愿望单」的款，角标恒为**已拥有**。
- ⚠️ 本地脚本 `scripts/sync.py` **不含愿望单** —— 它走的是云端接口。

## 自动归类规则（按优先级从高到低）

> 在这之前还有一条**最高优先级**：Steam 收藏夹「**已隐藏**」里的游戏，
> 以及被识别为工具/软件的（Godot Engine、Wallpaper Engine 等），
> 会被强制隐藏，不进任何状态区。可以用总览的「隐藏非游戏」开关控制显示。
> （「已隐藏」也是可改的，见 [收藏夹名字不一样怎么办](#收藏夹名字不一样怎么办)）

1. **🔒 你锁定的游戏** —— 锁上之后完全不动，连「已通关」也不重算
2. **🗑️ 放弃区的游戏** —— 手动终态，同步时同样一动不动
3. **已通关（归档）** —— 在「**已完结**」收藏夹里，或拿了全成就。
   **已通关是终态，永远不会被启动日期挪到其他区**
   （收藏夹名可改，默认认 Steam 自带的「已完结」）
4. **你手动改的状态（且之后没再启动过）** —— 尊重你的判断，同步不覆盖
5. **90 天内启动过** → 自动进「正在游玩」
6. **超过 90 天没启动** → 自动进「暂停区」
7. **从未启动过** → 停在「我的游戏单」，等你决定

### 启动日期自动归类（90 天规则）

这是自动分流的**主规则**，看的是 Steam 的「最后启动时间」：

```
最后启动 ≤ 90 天前   →  🔥 正在游玩
最后启动 > 90 天前   →  ⏸️ 暂停区
从未启动（时长 0）   →  留在「我的游戏单」
```

**想改阈值**：`js/store.js` 顶部一个常量搞定：

```js
const RECENT_DAYS = 90;   // 改成 60 就是两个月，120 就是四个月
```

改完需要同步一次（或清空后重新载入）才会全量重算。

#### 手动 vs 自动，怎么区分？

- **自动归类的卡片**：封面左下角有紫色「**自动**」角标
- **你手动设的**：没有这个角标
- 点开卡片能看到具体原因，比如「距上次启动已 117 天（超过 90 天）→ 自动归入「暂停区」」

#### 手动改完不会被覆盖

你手动把某款游戏挪到别处后，只要**没有再次启动过它**，同步就尊重你的选择。
一旦你重新启动了这个游戏，启动时间会更新，「自动」规则重新接管。

> 实现上记两个时间戳：`statusManualAt`（你手动改状态的时刻）与
> `lastPlayedTs`（上次启动）。前者更晚 → 保留手动；后者更晚 → 自动接管。

#### 🔒 锁定：永久钉死某个状态

如果某款游戏你想**永久固定**在某个状态（不管启动日期怎么变），
点开卡片 → 点「🔓 锁定状态」：

- 锁上后，同步时**完全跳过**它 —— 状态一动不动，「已通关」也不重算
- 卡片封面会显示金色「**🔒 锁定**」角标
- 再点一下解锁，恢复自动归类

适合场景：某款游戏你手动归了类，但担心以后哪天启动了又被系统挪走。

#### 🗑️ 放弃区：主动出局

有些游戏你**不会再玩了** —— 停服了、玩腻了、或者当年买亏了。
它们混在「暂停区」里会让那份清单越来越杂。

「放弃区」就是给这些游戏准备的：

- **只能手动进** —— 「不打算再玩了」是主观判断，Steam 数据里没有这个信号，
  所以不做自动归类（只有你能决定）。
- **进去就稳定** —— 放弃区是**手动终态**，和「锁定」同级：
  同步时一动不动，既不会被收藏夹（默认「已完结」）拉回「已通关」，
  也不会因为哪天手滑启动了一次就被挪去「正在游玩」。
- **随时能反悔** —— 点开卡片，点上面的状态按钮挪走即可，没有惩罚。
- 卡片左下角有灰色「**🗑️ 已放弃**」角标，一眼能认出来。

**怎么进**：点开卡片 → 状态按钮里选「🗑️ 放弃区」。

**批量进**（推荐）：暂停区里往往上百款，一款款点太累 —— 见下面的「批量选择」。

#### 批量选择（暂停区专用）

在「暂停区」右上角点 **「批量选择」**，界面进入选择模式：

```
[ ⬜ 卡片 ]  [ ⬜ 卡片 ]  [ ⬜ 卡片 ]

已选 4 / 32 款    点卡片选中 · 再点一次取消      [全选] [标为放弃] [退出]
```

- 点卡片 = 勾选 / 取消勾选（**不会**打开详情）
- 「全选」一次勾完当前列表；再点一次变成「取消全选」
- 「标为放弃」把选中的一次性移入放弃区（有二次确认）
- 按 `Esc` 或点「退出」结束选择模式

> 选择模式下切到别的区块会自动退出并清空选择 —— 避免"跨区选中"带来的困惑。

#### 「疑似已放弃」提示

暂停区里有些游戏停了**两年以上**（`js/store.js` 的 `STALE_DAYS = 730`）。
这些卡片左下角会多出一个**虚线样的「疑似已放弃」**角标，提示你去看一眼。

⚠️ **它只是个提示，不会自动归类** —— 你不动它，它就一直在暂停区待着。
觉得确实不玩了，勾上、标为放弃即可。

### Steam 收藏夹怎么读到的

同步脚本会读你**本机 Steam 客户端**的配置文件：

```
<Steam>/userdata/<账号ID>/config/cloudstorage/cloud-storage-namespace-1.json
```

这是本地文件，不需要 API Key，也不受 API 限流影响。脚本会自动探测
Steam 安装目录和账号目录，不用配置。

> ⚠️ 换机器、没装 Steam、或从没登录过该账号时读不到 —— 那时会跳过这一步，
> 其余归类照常工作。
>
> 🔧 **自动探测找不到 Steam 时**（装在非常规位置、绿色版、注册表被清理过），
> 在应用顶栏 **「设置」→ Steam 安装目录** 里手填一个即可，
> 或者点 **「扫描磁盘」** 让它自己找。见文末
> [Steam 装在哪不一样怎么办](#steam-装在哪不一样怎么办)。

脚本只负责把**收藏夹名原样**写进数据；「哪个名字代表什么状态」由你自己在
应用里定（顶栏 **「设置」**）。默认认 Steam 自带的「已完结」与「已隐藏」。

### ⚠️ 手动优先

一旦你手动给某个游戏设了状态，**Steam 同步永远不会覆盖它**。

如果你把某个游戏从「已通关」手动挪走，即使它还在「已完结」里，
**下次同步也不会把它拉回去**（除非你先在 Steam 里移出该分类、再加回去）。

## 总览的三个过滤开关

切到「我的游戏单」，标题行右侧会多出一个 **「筛选」** 按钮 ——
点开在标题下方展开三个开关（按钮上带数量）：

| 开关 | 关掉时 | 打开后 |
|---|---|---|
| 🙈 **隐藏非游戏** | 游戏 + 工具两段都显示 | 只剩游戏段，工具/软件全部藏起来 |
| 🙈 **隐藏已通关** | 已通关的照常显示 | 状态为「已通关」的全部不显示 |
| 🙈 **隐藏已放弃** | 放弃区的照常显示 | 状态为「放弃区」的全部不显示 |

三个开关互相独立、可以任意叠加。灰字显示的是**打开后会藏掉的条数**，
点一下切换，状态实时生效。数量为 0 的开关不会出现。

> 收起时**不占任何高度**；有开关生效时按钮变琥珀色并显示个数角标。
> 面板内的选项只建一次，所以点选项不会把面板弹回去。

> 「隐藏已放弃」适合配合「我的游戏单」当**主浏览入口**：把已经出局的和
> 看过的都收走，剩下的才是真正还在清单上的东西。

> 「隐藏已通关」是**按状态判定**的 —— 只要状态是「已通关」就藏起来，
> 跟它是不是全成就无关。所以它会把收藏夹（默认「已完结」）带来的
> 和手动标记的，一起收走。

> ⚠️ 开关的**默认值是不隐藏**（三个都关）—— 打开应用看到的是完整清单。
> 开关状态不会持久化，刷新后回到默认。想固定住就用 URL 参数（见下）。

## 排序与分组

右上角五个排序维度：

| 维度 | 说明 |
|---|---|
| 最近游玩 | 按最后启动时间倒序 |
| 游玩时长 | 按总时长倒序 |
| **成就进度** | 全成就打头，其次按完成率降序，无成就数据的垫底 |
| 名称 | 按中文拼音排序 |
| 发售年份 | 按年份倒序 |

### 「已通关」区：全成就分组

在「已通关」区右上角会多出一个 **「分组：全成就」** 开关。打开后
卡片分成两段，各带标题和计数（🏆 全成就 / ◈ 未全成就）。

> 配合「成就进度」排序用最舒服 —— 排序负责顺序，分组负责视觉分隔。

### 用 URL 参数直达

支持直接把某个视图状态存成书签：

| 参数 | 作用 | 例子 |
|---|---|---|
| `view` | 打开哪个区块 | `?view=completed` |
| `sort` | 排序维度 | `?sort=achievement` |
| `group` | 已通关区开启分组 | `?group=1` |
| `hidetools` | 总览隐藏工具/软件 | `?hidetools=1` |
| `hidedone` | 总览隐藏已通关 | `?hidedone=1` |
| `hidedrop` | 总览隐藏已放弃 | `?hidedrop=1` |
| `select` | 进批量选择模式（暂停区） | `?select=1` |
| `storage` | 强制走 localStorage（排障用） | `?storage=local` |
| `local` | 强制本地模式（不走云端登录门） | `?local=1` |

组合示例：
- `index.html?view=completed&sort=achievement&group=1` —— 已通关区、按成就排序、全成就分组
- `index.html?view=library&hidedone=1` —— 总览只看还没通关的
- `index.html?view=library&hidetools=1&hidedone=1&hidedrop=1` —— 纯游戏、纯未通关、且没放弃
- `index.html?view=paused&select=1` —— 直接进暂停区的批量选择模式

> 📌 用 `file://` 双击打开时**一律走本地模式**（云端登录需要已注册的 HTTPS 域名，
> `file://` 下拿不到会话）。

## 数据存在哪

全在**你本机浏览器**里（IndexedDB，降级走 localStorage）。

- 不联网、不上传、不需要账号
- 换浏览器/清缓存会丢 —— 重要记录建议定期用「设置 → 数据备份 → 导出到文件」存一份
  （`data/steam_sync.json` 只含 Steam 数据，手写感想不在里面）

| **标为放弃**（不打算再玩了） | 点开卡片 → 状态按钮选「🗑️ 放弃区」 |
| **批量标放弃** | 暂停区右上角「批量选择」→ 勾选 → 「标为放弃」 |
| 写感想 | 点开卡片 → 「我的游玩记录」→ 编辑 |
| 搜索 | 顶部搜索框，或按 `/` |
| 排序 | 右上角五个维度切换 |

| 藏掉工具/软件 | 总览标题行「筛选」→「🙈 隐藏非游戏」 |
| 藏掉已通关的 | 总览标题行「筛选」→「🙈 隐藏已通关」 |
| 藏掉已放弃的 | 总览标题行「筛选」→「🙈 隐藏已放弃」 |
| **改收藏夹归类**（哪个收藏夹算「已通关」） | 顶栏「设置」 |
| **改 Steam 安装目录**（自动探测不到时） | 顶栏「设置」→ Steam 安装目录 |
| 看历史提示 | 顶栏「消息」 |
| 删除游戏 | 点开卡片 → 右下「删除」 |
| **清空全部游戏记录** | 顶栏「设置」→ 最底部 **「危险操作」** → 还要过一次确认窗 |
| **备份 / 换电脑搬数据** | 顶栏「设置」→「**数据备份**」→ 导出到文件 / 从文件导入 |

> 💾 **备份为什么在设置里，而且紧贴着「危险操作」**
> 它原来只是页脚的一个小文字链（还是个没样式的原生按钮），而它的对偶「从文件导入」
> 却藏在「同步」弹窗里 —— 一件「换电脑搬数据」的事被拆到两个地方，两边都难找。
> 现在两个动作都在**设置 →「数据备份」**一节里，而且**刻意贴在「危险操作」正上方**：
> 滚下去准备删东西的时候，先看到「备份一份」。
>
> 导出的文件**自带收藏夹设置**（哪个收藏夹算「已通关」）—— 少了它，新机器会按默认名
> 重算归类，你的「已通关」会整片落回「我的游戏单」。文件里也带着每款的 **status**，
> 导入时**沿用文件里的**而不是重新推算，所以手动标的「已通关 / 放弃」搬过去还是原样。
>
> 导入是**合并**不是替换：文件里多出来的款新增进来；同 appid 的记录会被文件里的覆盖，
> 但你**手动标记过的状态、锁定的记录不会被覆盖**。空文件、坏文件都只给中文提示，
> 不会动你现有的数据。

> 🔴 **「清空全部游戏记录」为什么藏得这么深**
> 它原来就挂在右上角那个「⋯」上 —— 和「同步」「设置」并排的一个小点，点下去是全库蒸发。
> 误触的代价太大，所以现在：**入口在设置的最底部**（要主动滚下去）、**整节走红色**
> （一眼看出和上面的设置项不是一类）、点开还要过一层**独立的确认窗**：
> 先告诉你**会删掉什么**（多少款记录、其中多少条手写感想 —— 都是现算的真数字），
> 再告诉你**不会动什么**（Steam 账号与 Key、Steam 安装目录、收藏夹设置、消息记录），
> 最后要**勾掉一个框**「确认清空」才会亮起来。
> 取消、点空白、按 `Esc` 都算放弃；`Esc` 只收掉确认窗，不会连设置一起关。
> 清空这件事也会记进顶栏「消息」里，事后能翻到。
>
> 手滑了的话：**「设置 → 数据备份 → 从文件导入」** 可以把之前导出的 JSON 导回来。

## 已知限制

- **愿望单导入只在云端版** —— 本地脚本 `sync.py` 不含它
- **读不到游戏进度**（打到第几章）—— 只能用成就完成率做粗略估计
- **部分游戏没有成就系统** —— 那就只能手动标记「已通关」
- **部分游戏补不到发售年份** —— 下架游戏、DLC、工具类在 Steam 商店无数据
- **收藏夹依赖本机 Steam 客户端** —— 换机器或没装 Steam 就读不到；但读了也不影响其他归类
- **收藏夹里有些 appid 不在库里** —— 退库/隐藏的游戏会有残影，匹配到才生效，不匹配自动忽略
- **「放弃」没法自动判** —— Steam 数据里没有「我不想玩了」这个信号，所以放弃区纯手动进；
  暂停区里停两年以上的只挂一个「疑似已放弃」提示角标，不会自动归类

## 收藏夹名字不一样怎么办

**不用改代码。** 顶栏点 **「设置」**，填两个框就行：

| 设置项 | 默认值 | 作用 |
|---|---|---|
| 归入「已通关」的收藏夹 | `已完结` | 在这个收藏夹里的游戏自动进「已通关」 |
| 视为「已隐藏」的收藏夹 | `已隐藏` | 在这个收藏夹里的游戏强制隐藏，不进任何状态区 |

两个默认值都是 **Steam 自带**的分类名，所以大多数人开箱即用。

- **可以填多个**，用逗号隔开（中英文逗号、顿号都认）。
- **不用记名字**：设置里会列出你数据里实际出现过的收藏夹，点一下填进去。
- **点保存后当场重算**已同步的数据，不用等下次同步；提示条会告诉你
  有几款新归入、几款移出「已通关」。
- 设置存在**本机浏览器**里（不进账号、不上传）。导出到文件时会一并带上，
  换设备导入备份就跟着走了。
- ⚠️ **多设备各设一次**：它不像游戏数据那样云端同步，所以在另一台设备上
  也要设一遍，否则那台会按默认名重算归类。

> 早期版本把「已通关」的收藏夹写死成「完结撒花」。现在**如果你数据里确实
> 有这个名字**，应用会自动把它一并认下来（是**追加**，不会覆盖默认值），
> 老数据里的「已通关」因此不会掉出去；只要你亲手保存过一次设置，就不再自动改。

改完收藏夹名后**不需要**重跑 `sync.py` —— 收藏夹名是每次同步都会重读的，
设置里的名字才是判据。

## Steam 装在哪不一样怎么办

**大多数人不用管。** 应用按这个顺序自己找，前三步能覆盖绝大多数机器：

1. 你在应用里**指定过的目录**（存下来了，以后一直用它）
2. **注册表**：当前用户的 `HKCU\Software\Valve\Steam`，
   以及本机的 `HKLM`（含 64 位视图与 `WOW6432Node` 32 位视图）
3. **常见安装路径**（`C:\Program Files (x86)\Steam`、`D:\Steam` …）

> 第 2 步的 `HKLM` 那一档不是多余的：Steam 若是**另一个 Windows 账户**装的，
> 你自己的 `HKCU` 里就没有它，而 `HKLM` 是机器级的，任何账户都读得到。

万一还是找不到（绿色版、装在非常规位置、注册表项被清理软件删过、
一台机器上有多份 Steam），顶栏 **「设置」→ Steam 安装目录**：

| 你会看到 | 说明 |
|---|---|
| **状态行** | 现在用的是哪个目录、是**自动检测到的**还是**你指定的**，一目了然 |
| **输入框** | 填 **Steam 安装目录** —— 就是里面有 `steam.exe` 的那一层 |
| **「扫描磁盘」** | 让应用自己去各个盘找一遍，找到的列出来，点一下就填进输入框 |
| **「改回自动检测」** | 清空你的指定，回到上面那套自动流程 |

几个已经替你处理好的坑：

- **填错一层没关系**：选到 `…\Steam\steamapps`、`…\Steam\steamapps\common`
  甚至直接选中 `steam.exe` 本身，都会自动往上找到安装目录。
- **从资源管理器地址栏直接粘**：带引号、正斜杠、尾斜杠、`%ProgramFiles(x86)%`
  这类环境变量都会被收拾干净。
- **填错了不会被存下来**：点保存时会先验证，不合法就**当场告诉你为什么**
  （目录不存在 / 这是游戏库目录不是安装目录 / 里面没有 `steam.exe`），
  并且**原设置不动** —— 不会因为一次手误就把能用的配置清掉。
- **填的那个目录后来没了**（换盘、被搬走）不会卡死：自动回落到自动检测，
  并在状态行里说明「你之前指定的目录已不可用」。
- **路径大小写会还原**：注册表里存的是全小写（`d:\program files (x86)\steam`），
  显示时按磁盘上的真实大小写写出来。

> 📌 **脚本和应用共用这一个设置。** 应用里设过之后，`scripts/sync.py`
> 也会优先用它（命令行仍可用 `--steam-root` 临时覆盖）。设一次，两边都认。

> 🔒 这个设置只存在**本机**（Windows 上是
> `%LOCALAPPDATA%\MyGameVault\desktop.json`），只有一条路径，不含账号或密钥。
> 应用里的「数据备份 → 导出到文件」不会带走它 —— 那是**这台机器**的属性，
> 换一台机器本来就该重新检测。

## 桌面版为什么固定用 47615 端口（很重要）

桌面版（`desktop/main.py`）只监听本机回环，端口固定为 **47615**：

**浏览器是按「源」隔离本地数据的，而源里含端口** ——
`http://127.0.0.1:47615` 和 `http://127.0.0.1:47616` 是两个互不相干的源。
端口一变，你之前的游戏库、状态归类、感想、收藏偏好、消息历史就**全都看不见了**。
早期版本用「系统分配的空闲端口」，结果**每次启动都是一个新源**，
等于每重启一次就清空一次 —— 实测同一个浏览器配置下，
在 `:11701` 写入的值，到 `:11730` 读回来是空的。

| 情况 | 应用的行为 |
|---|---|
| 端口空闲 | 正常启动 |
| 端口上是**本程序的另一个实例** | 直接连上它（不会起第二个服务抢端口），你看到的是同一份数据 |
| 端口被**别的程序**占用 | **停下来明确告诉你**，并给出解决办法；**不会偷偷换端口** |

> 换端口 = 换一份存储。旧数据并没有被删，把端口换回去它就还在。
> 确实需要换（比如 47615 被占又关不掉那个程序）：`python desktop/main.py --port=<端口>`。

> 自动化测试用 `--port=0`（随机端口）来互相隔离，这是**测试专用**用法，日常请不要这样启动。

## 桌面版：同步按钮点一下就同步

桌面版的应用进程**本来就能直接读你的硬盘**，所以点顶栏的**「同步」**之后不需要再选任何文件 ——
面板开着就把本机 Steam 数据读完了（这是**自动**的，你甚至可以先什么都不点，面板打开时它已经跑完了）。

面板里会如实列出这一轮到底干了什么：

```
同步完成：共 1200 款（联网新补 600 款）。
本机 Steam                              620 款
已安装 / 有名字 / 有封面 / 有时长        48 / 600 / 520 / 500
新增 / 更新                             0 / 620
Steam 账号全量                          900 款（新增 600）
```

### 绑一个 Steam 账号，能多出一批「买了但从没碰过」的

本机 Steam 文件只记录**装过 / 玩过 / 在收藏夹里**的款，所以光读本机会少一批游戏
（本机那份里没有、账号侧那份里有的，就是这些）。

想补全就在**设置 →「Steam 账号（可选 · 联网同步用）」**里填两样：

| 填什么 | 怎么拿 |
|---|---|
| **SteamID** | 直接填 `7656119…` 这串数字；填个人资料链接或 `/id/xxx` 也行，点「验证并保存」会帮你解析 |
| **Steam Web API Key** | 在 [Steam 官方页面](https://steamcommunity.com/dev/apikey) 免费申请（32 位十六进制） |

点**「验证并保存」**会先解析 ID、顺便验一次 Key 通不通，**都通过了才存**。填错（比如把 SteamID
粘进了 Key 那一栏）会当场告诉你哪里不对，而不是等到同步时报一个看不懂的错。

> **不填也完全能用** —— 只是少了那批「买了没碰过」的。没绑账号时面板会直接写明「未绑定账号」，
> 不会静默跳过。

关于这两样东西的安全：

- **只存在这台机器上**（`%LOCALAPPDATA%\MyGameVault\desktop.json`），不会上传、不进日志。
- **界面永远不回显 Key** —— 服务端只回「有没有填」这一个布尔值，所以你打开设置时 Key 框是空的
  （留空 = 不改动，想换就粘个新的进去）。要清空请用「清除账号」。
- ⚠️ 但它在**本机是明文**，和浏览器记住的密码一个性质。共用电脑请留意。
- 用户自己填的 Key **优先于**项目 `.env` 里的那份（`.env` 是自用/线上用的，对外发的桌面版不带它）。

### 文件入口保留了，但它是「导入备份」用的

面板底下那个「选择文件」还在 —— 用于**换机器**时导入以前用「设置 → 数据备份 →
导出到文件」存下的 JSON。日常同步不用管它。

> 面板底部那一行的两个按钮：**「重新同步」**再跑一次；**「账号设置」**直接跳到上面那节。

## 桌面版：名字和封面会联网慢慢补全

Steam 的本地文件里，**只有「装过 / 玩过 / 在某收藏夹里」的款才有记录，其中又只有已安装的款带名字**。
所以第一次打开桌面版时，不少卡片会显示成 `App 1234567` 这样的**占位名** —— 这不是出错，
是本地确实没有那个名字。

应用会在**后台**分批联网去问商店接口（免 key，不需要你填任何东西）：

| 你会看到 | 说明 |
|---|---|
| 占位名 `App <id>` 逐渐变成真名字 | 每次启动最多补 **45 款**，几百款要几轮才能补完 |
| 进度**关机不丢** | 已经问过的记在本机，下次接着补，不会每次从头再来 |
| 补完会给一条消息提示 | 顶栏「消息」里能回看 |

两个已经替你处理的细节：

- **只补缺，不覆盖。** 本机已经有封面（离线可看的那种）的款，**不会**被换成商店的远程图片 ——
  否则「离线版」会变成「不联网就看不到图」。你已有的名字也不会被改名。
- **联网不通时不会卡住。** 商店域名在有些网络里会被拦，这时应用**首波没答复就收手**，
  并记住 6 小时不再试 —— 不会每次启动都干等 100 秒。本机其它功能完全不受影响。
  等网络恢复了，下次启动会自动继续补。

## 桌面版：打包成 exe（双击就能用，不用装 Python）

```bash
# 依赖装到隔离 venv 里（别动系统 Python）
python -m venv .venv-desktop
.venv-desktop/Scripts/python -m pip install pyinstaller pywebview

# 出包
.venv-desktop/Scripts/python scripts/pack_win.py
```

产物在 **项目外面**：`../_build_desktop/dist/gamevault-desktop/`（约 38 MB）。
里面的 `gamevault-desktop.exe` 双击就跑 —— ⚠️ **整个目录一起拷走**（`_internal/` 不能丢）。

打包脚本走**白名单**：只把前端静态资源 + `server/` 的代码装进去，
`server/` 是以编译进包的形式（源码不以明文落在 `_internal/` 里）。
包出来会自动做**两次泄露体检**（打包前一次、打包后一次），
查 `.env` / `js/seed-data.js` / `desktop.json` / SteamID / 32 位十六进制串，
任一不过就拒绝出包。

> ⚠️ **别拿 `scripts/pack_deploy.py` 出 exe**：那是给**线上服务**用的白名单，
> 它**故意包含 `.env`**（服务端要用它代表访问者去查 Steam）。
> 桌面版是发给别人用的，带上 `.env` 等于把 API Key 送出去 —— 两个脚本白名单刚好相反。

### 出包时踩过的两个坑（已修，别再犯）

1. **pywebview 默认不会把数据存在磁盘上。** 它 `start()` 的默认参数是
   `private_mode=True` + 没有 `storage_path`，Windows 后端遇到这个组合会用**临时目录**
   （而且每次启动换一个）再开隐身模式 —— 结果是**你存的库、状态、感想，关掉窗口全没了**。
   所以 `desktop/main.py` 里固定传了 `private_mode=False, storage_path=%LOCALAPPDATA%\MyGameVault\webview`。
   🔴 这两个参数**缺一不可**。它和「端口必须固定 47615」是**两条独立的存储**：
   端口那条管的是浏览器存储的「源」，这条管的是 WebView2 自己那套。
2. **打包后 `__file__` 不再指向项目目录。** `server/config.py` 的 `BASE_DIR` 和
   `desktop/main.py` 的 `ROOT` 都靠它找静态文件，冻结后算法不一样 → 已加 `sys.frozen` 分支。
   不加的表现是：exe 打开**一片白**，或一启动就退。

### 怎么发给别人试用（出分享包）

```bash
python scripts/pack_share_zip.py --verify
```

产物 `../_build_desktop/share/GameVault-试用版-<日期>.zip`（约 14.5 MB，微信/QQ 直接发得动）。
包里是 `使用说明.txt`（放 **zip 根**上，解压第一眼就看见）+ `gamevault-desktop/` 整个目录。

🔴 **不能只发 exe** —— 反向对照实测：单独把 exe 拷出来会报
`Failed to load Python DLL '...\_internal\python313.dll'` 然后退出（退出码 -1）。
（那行系统错误文本本身还是乱码的，所以说明书里写的是「看到 `Failed to load Python DLL`
就是这个原因」，而不是照抄系统原文。）

那份说明书替你讲了收包人最容易卡住的四件事，每条都是实测出来的：
SmartScreen 要点「更多信息 → 仍要运行」；exe 不能单独拖出来；**首屏是空的要点「同步」**
（数据来自他本机 Steam）；数据存在他本机 `%LOCALAPPDATA%\MyGameVault`、出问题先别关那个黑窗。

脚本干三件事：压之前**复用 `pack_win` 的体检规则**再查一遍（规则不重抄一份，
免得两套分叉成「出包拦住了、发的时候放过去了」）→ 压完**从 zip 里读回来**验结构 / 夹带 /
说明书文件名编码 → 打印 SHA-256（对方说打不开时先核这个值）。
`--verify` 会顺带解出一份并打印 exe 路径，可以接着跑
`python _e2e_desktop_exe.py --exe <那个 exe>` 证明压出来的能跑。

⚠️ 中文路径验过：解到 `…\GameVault 试用版（分享包）\`、数据目录也用中文名，
`_e2e_desktop_exe.py --home <中文目录>` 依然 **18 PASS / 0 FAIL**
（e2e 的 `--home` 参数就是为复现「中文用户名」这种真实环境加的）。
